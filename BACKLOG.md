### 2. Dexie: добавить `upgrade()` колбэки
Текущее состояние: `version(1)` без стратегии миграции.
При любом изменении схемы и поднятии версии — без `upgrade()` APP_INITIALIZER падает при первом запуске
(на вызове `db.open()`). Данные пользователя при этом не теряются (транзакция схемы атомарна),
но приложение не открывается, пока версия не сойдётся.
**Действие:** написать `upgrade()` заготовку уже в version(1), задокументировать паттерн.

### 3. ReadinessScore: добавить флаг критического дефицита
Текущая аддитивная модель: аптечка на нуле + всё остальное на 100% → итог ~82%.
Число технически верное, но вводит в заблуждение.
**Действие:** если любая категория с приоритетом High (Water, Food, Medical) ниже порога
(~20% от цели, то есть ниже 72-часового минимума по нормам ГО), дашборд показывает отдельный
флаг «критический дефицит» независимо от итогового индекса.
Число остаётся — для навигации. Флаг — для действия.

### 4. Перенести веса из хардкода в `TargetLevel`
Несогласованность: нормы (TargetLevel) живут в таблице и редактируются пользователем,
веса захардкожены в `ReadinessScoreService` как `private static readonly Dictionary`.
Оба параметра — одного типа («насколько важна эта категория»), решены двумя разными способами.
**Действие:** добавить колонку `Weight decimal NOT NULL DEFAULT 1` в таблицу `TargetLevel`,
перенести туда константы из словаря, `ReadinessScoreService.Calculate()` принимает веса
из тех же данных, что и нормы.
