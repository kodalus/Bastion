### 3. Dexie: скелет `upgrade()` и явное версионирование
Текущее состояние: `version(1)` без стратегии миграции.
При поднятии версии без `upgrade()` — `APP_INITIALIZER` падает на `db.open()`.
Данные пользователя при этом не теряются (транзакция схемы атомарна), но приложение не открывается.
**Действие:** написать `upgrade()` заготовку уже в `version(1)`, задокументировать паттерн
для будущих изменений схемы.

### 5. Порог критического дефицита и нерасходуемые категории
**Порог для расходуемых (Water, Food, Medical, Hygiene, Energy):**
Привязать к 72-часовому минимуму ГО, а не к произвольному проценту.
72 часа от 14-дневного целевого уровня ≈ 21% — это не выдуманная цифра, а норма гражданской обороны.

**Открытый вопрос — нерасходуемые категории (Documents, Tools):**
Формула `quantityPerPersonPerDay × horizonDays` не имеет смысла для документов и инструментов.
У них нет расхода — они либо есть, либо нет.
Нужно добавить к `TargetLevel` признак `IsConsumable`:
- Расходуемые: текущая формула + порог 72 часа.
- Нерасходуемые: готовность бинарная (`available >= required` → 100%, иначе 0%).
  Критический флаг срабатывает при любой нехватке, а не при падении ниже порога.

### 6. Веса: перенести из хардкода в `TargetLevel` — три следствия
Текущая несогласованность: нормы живут в таблице и редактируются пользователем,
веса захардкожены в `ReadinessScoreService` как `private static readonly Dictionary`.
**Действие:** добавить колонку `Weight decimal NOT NULL DEFAULT 1` в `TargetLevel`.

**Следствие 1 — миграция:**
`DEFAULT 1` даст всем существующим строкам одинаковый вес. Индекс сразу после миграции покажет
равновзвешенный результат. Нужна data-миграция в том же файле — явные UPDATE для каждой категории.

**Следствие 2 — произвольная сумма весов:**
Формула `Σ(score × weight) / Σ(weight)` — взвешенное среднее, математически корректна
при любой сумме. Сумма 11 нигде не захардкожена, сломаться не может.

**Следствие 3 — обнуление категорий пользователем:**
Пользователь может выставить `Weight = 0` для Medical, и аптечка выпадет из расчёта.
Решение: заморозить веса категорий с приоритетом High (Water, Food, Medical) — не редактируются.
Для Medium и Low — разрешить настройку, но с минимумом `Weight >= 0.5`.
